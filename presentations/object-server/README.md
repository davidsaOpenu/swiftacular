# The Swift Object Backend

Source for the presentation of the same name. The deck is a
[Marp](https://marp.app/) markdown file; the diagrams are
[d2](https://d2lang.com/) sources rendered to SVG at build time.

## Layout

```
slides.md        the deck itself: front matter, slides, image references
graphs/*.d2      diagram sources, one per slide that needs one
graphs/*.svg     rendered diagrams -- build output, not checked in
images/          static images used as-is
build.sh         the task runner (see below)
container/       image definition, if you would rather not install the tools
```

## Building

`build.sh` is a small task runner. Tasks are run at most once per invocation, so
dependencies between them are not repeated.

```sh
./build.sh              # same as ./build.sh ci
./build.sh render       # graphs/*.d2 -> graphs/*.svg
./build.sh build        # render, then slides.md -> slides.pdf
./build.sh watch        # live preview; re-renders diagrams too
./build.sh clean        # remove rendered SVGs, slides.pdf, slides.html
```

`ci` is `build` plus the bookkeeping the pipeline expects; for day-to-day work
use `build` or `watch`.

You need `d2` and `marp` on your `PATH`, plus a browser for PDF export — Marp
drives a headless browser to print. The versions the deck is known to render
correctly with are pinned in `container/Dockerfile`; if you install by hand,
match them.

## Writing slides

`slides.md` opens with Marp front matter — theme, pagination, and a `style`
block that drops the base font size to 22px and tightens padding, which is what
makes the denser slides fit. Slides are separated by `---`.

Images are referenced with plain markdown. Marp reads the alt text as sizing
directives, which is how the taller diagrams are kept on the page:

```markdown
![](graphs/slide03.svg)         <!-- natural size -->
![h:540](graphs/slide05.svg)    <!-- scaled to 540px tall -->
```

If a diagram spills off the bottom of a slide, `h:` is the first thing to reach
for. The values in the deck were found by eye — there is nothing magic about
540.

## Diagrams

Each `graphs/slideNN.d2` corresponds to slide `NN`, counting from the title
slide. The numbering is positional and there are gaps where a slide needs no
diagram or uses a static image, so inserting a slide in the middle means
renaming the files after it. The deck is written once, so this has been left
alone deliberately.

`render` runs `d2 --pad 0` over every source, which writes the SVG next to it.
The `--pad 0` matters: d2's default padding is generous and wastes vertical
space that the slide does not have.

Only the `.d2` files are checked in. The SVGs are gitignored — treat them as
output and never edit them by hand.

## Static images

`images/` holds anything not generated from a d2 source. `classtree.svg` is
graphviz output from running pyreverse against the Swift source tree; it is
committed rather than built, because reproducing it would mean having that
source tree available at build time. If the class hierarchy changes, it has to
be regenerated by hand.

## Notes

- `watch` runs `d2 --watch` on every diagram alongside `marp -w`, so edits to
  either `slides.md` or a `.d2` source show up in the preview.
- Both Marp invocations redirect from `/dev/null`. Marp otherwise reads stdin
  and will sit there waiting when run non-interactively.
- `build` passes `--allow-local-files`, without which the headless browser
  refuses to load the SVGs and images off disk and the PDF comes out with
  everything missing.
